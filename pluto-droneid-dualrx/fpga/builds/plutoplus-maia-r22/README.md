# Pluto+ Maia R22 DroneID FPGA candidate

This folder preserves the one-channel FPGA candidate and a separate SD-card
file set. The Tezuka Pluto+ source FPGA projects were left intact; the new XSA
was added under its own name in the DroneID Tezuka clone so Buildroot can
produce an alternate SD bitstream.

## Contents

- `droneid-maia-r22.xsa` and `droneid-maia-r22.bit`: generated by the successful
  Vivado 2023.2 implementation.
- `sdimg/`: refreshed Tezuka Pluto+ SD boot files, including the rebuilt
  ramdisk with `pluto-droneid-tx`, `pluto-droneid-count`, and test waveforms.
  `uEnv.txt` selects `droneid-maia-r22_top.bin`. The original default
  `system_top.bin` was restored byte-for-byte after the post-image build
  (SHA-256 `c49d150a...cef40aa87`); `tezuka_top.bin` and
  `system_top_top.bin` remain alongside it.
- `fpga-source/` and `reports/`: the RTL, integration script, and routed
  reports corresponding to the candidate.
- `work/`: the extracted bitstream and Bootgen input used to create the SD
  format `.bin` file.

To try the FPGA candidate, copy the *contents* of `sdimg/` to a separate FAT32
card and boot it in SD mode. This folder is the SD boot file set; it is not a
raw whole-card disk image. The Tezuka Buildroot post-image stage generated the
boot files and alternate bitstream, and the candidate copy's `uEnv.txt` selects
`droneid-maia-r22_top.bin`.

The Buildroot update was made in the separate `tezuka_fw-droneid` clone. Its
original `system_top.xsa` and default SD payload are preserved. Only the
candidate copy's `uEnv.txt` selects the DroneID bitstream. No card was flashed.
Use the SD files in this folder for the test; do not use the regenerated flash
`.frm`/`.dfu` files in the Buildroot output.

The design uses one RX chain for detection. It passed RTL simulation and
Vivado routing, but has not been tested on the Pluto hardware. See `reports/`
for resource, timing, DRC, and methodology reports.
